# Structural measurements

Speech recognition for .NET. Unaffiliated with other products or companies named OneSpeech.

This BCL-only runner measures the real pipeline rather than a microbenchmark loop. Build a separate, non-AOT Release output with `-p:OneSpeechGraphTiming=true`. Do not package that instrumented core. A normal build has **no timing call sites or argument evaluation**: `Conditional` removes them at compile time. The internal hook lives in `src/OneSpeech/GraphTiming.cs`; only this runner and tests can access it. No public API changes are needed.

```sh
dotnet build bench/OneSpeech.Bench -c Release -p:OneSpeechGraphTiming=true
dotnet "$ONESPEECH_ARTIFACTS/bin/OneSpeech.Bench/release/OneSpeech.Bench.dll" \
  --prepare-data "$LIBRISPEECH_TEST_CLEAN" "$AMI_MIX_HEADSET" "$DATA"
dotnet "$ONESPEECH_ARTIFACTS/bin/OneSpeech.Bench/release/OneSpeech.Bench.dll" \
  --filter all --threads 1 --data "$DATA" --out "$RESULTS"
```

Filters: `turbo60`, `turbo600`, `long`, `small`, `qwen`, `live`, `diarize`, `align`, or `all`. Each filter is a separate process for queue-sized runs. Repeat with the selected multithread count. `long` is a dense 3600-second file; it can take substantially longer than the shorter filters. A timeout does **not** produce a passing row; its flushed memory trace is only partial evidence.

Set `ONESPEECH_MODEL_CACHE` to the verified local cache. `--pull MODEL_ID` fetches publisher assets at catalog pins and converts locally. `--link MODEL_ID EXISTING_DIRECTORY` creates a cache symlink to an existing complete model directory; `PullAsync` still verifies it. Never copy weights between machines for these runs. `tools/scripts/setup-arm64-bench.sh STATE_DIRECTORY` installs a pinned, hash-verified user-local arm64 SDK and fetches the pinned minimum data on the destination. Model acquisition uses the same runner there, without credentials.

## Method

- Inputs: the first 60, 600 and 3600 seconds of ordinal-path-sorted LibriSpeech test-clean utterances, concatenated without inserted silence; the full AMI ES2004a Mix-Headset recording. Mono 16 kHz PCM16 conversion is deterministic, with source and derived SHA-256 manifests. The final utterance can be truncated. Alignment uses the corresponding text including that final utterance. Keep upstream corpus licence/attribution notes alongside the derivatives. No quality claim is made on these constructed workloads.
- Turbo uses `Speech.Transcribe` with its default model; small and Qwen select their catalog IDs. Timing and diarization are included. Alignment explicitly selects omniASR; the ordinary English alignment default can select a different model. Clustering uses the same default `ClusteringDiarizer` configuration and the diarization-specific VAD profile. It includes full-file decoding, features and clustering, not just embedding inference.
- Missing asset download/conversion and initial checksum verification are recorded separately (`prepareSeconds`). Static file helpers reopen graph sessions during the measured call; their model loading **is included** in end-to-end time, not hidden in warm-up. ASR receives one 10-second warm call before measurement. This is a file-call row, not a retained-session throughput row. Non-ASR file rows include cold session construction. Live warms the exact 60-second input in another session, then measures fresh live state on retained graph sessions.
- Summed graph time brackets synchronous OneModel `Session.Run` calls for Whisper (both encoder parts and decoder), Qwen (including its aligner), omniASR, CAM++/ECAPA, Moonshine and Silero. The split Whisper encoder brackets each call separately (absent optional parts are not counted). Input expressions evaluated at the call (small dictionaries) are included; feature extraction, tensor preparation outside the call and output postprocessing are excluded. Graph time is wall time, never the sum of worker-thread CPU time. The opt-in thread override applies to these family graph sessions; Silero remains at its production one-thread setting.
- The five exclusive coarse non-graph cost buckets are model loading, front-end features, CTC postprocessing/trellis, clustering/resegmentation and audio decoding/resampling. `unattributed` contains search, tokenizer work, other tensor preparation, JSON-independent result construction, disposal and measurement overhead. These are not a sampling profiler and do not claim to identify individual methods inside that residual. Higher-level file phases independently subtract graph time; **do not add phase and exclusive costs together**. One row/pipeline runs at a time in a process.
- Live uses 100 ms chunks, includes `Complete` in elapsed time, and discards the first 100 chunks from allocation accounting. Graph allocation is the calling thread's allocation delta inside each graph call; model-worker allocations are not falsely attributed to our code. Immutable emitted payloads are accounted by replaying the owned payload graph after `Push`, using the existing live allocation harness method. Both emitting and non-emitting working bytes, event-independent chunk counts, and process allocations are reported. Payload replay overhead remains in end-to-end time, making the ratio conservative. The harness allocates input views before the measured push; it never pools emitted events.
- Memory is sampled every five seconds and flushed to CSV throughout the run. `sampledPeakWorkingSetBytes` is explicitly a sampled peak; `processLifetimePeakBytes` includes preparation/warm-up and uses the OS process high-water mark. The steady range starts at 30 seconds and is not itself a proof of flat memory: inspect the trace, especially the separate recognition/alignment/diarization passes and their changing model residency. Very short rows fall back to the sampled peak for both bounds.
- JSON carries input digest, model revision, precision, thread count, CPU/ISA, SDK/runtime/library versions, core count, load before/during/after, graph-call counts, time, allocations, memory and RTF. Matching CSV and Markdown summarize each row. Failures stop rather than emit plausible-looking rows with zero graph time. Outputs belong outside the source tree.

These runs are indicative until collected under the release benchmark protocol on an otherwise idle machine. Shared-load results must not be presented as final speed bars. A ratio above 1.15 or a nonzero working allocation is reported, not optimized away by this runner.
